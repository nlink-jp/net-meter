# ADR-0004: パネルを SwiftUI の MenuBarExtra の窓に載せ替える

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-09-21 |
| Binds | net-meter |
| Supersedes | ADR-0003 の決定 1・3・4・5・6（器と、器を自前で持つことに伴っていたもの） |
| Decision makers | nlink-jp maintainers |
| Triggered by | 利用者の報告:「よくよく見ると、パネルを開くときにアイコンのハイライトが明滅するか外れている」— net-meter・load-spinner・task-clock-gui で起き、MenuBarExtra のアプリでは起きない |

## Context

macOS 27.0、2026-09-21 に実測（項目の矩形だけを 60 fps で撮影）:

- 非アクティブ化 `NSPanel` では、押している間だけ項目が点き、離した瞬間に消えて、パネルを開いている
  間ずっと消えたまま（5 回中 5 回）。
- 開いている間のハイライトは、`NSPopover` と SwiftUI の `MenuBarExtra` が、それぞれフレームワークの
  内側で AppKit の非公開の仕組みを使って保っている（lldb で呼び出し元まで確認）。`NSButton.highlight(_:)`
  と `isHighlighted` は画面に出ない（呼ぶ時機を 5 通り変えて各 3 回、すべて消灯）。
- popover が使う非公開の呼び出しをパネルに対して行っても点く。ただし採らない — このプロジェクトは
  非公開 API を使わない。
- ADR-0003 が `NSPopover` を離れた理由は、パネル内の最初のクリックがアプリをアクティブ化し、開いた
  ポップアップメニューを終わらせることだった。LaunchServices 起動直後に同じ操作をすると、popover の
  対照は 88〜97 ms でメニューが閉じ、直後にアクティブ化した（2 回中 2 回、ADR-0003 の 78 ms を再現）。
  `MenuBarExtra` の窓では、閉じるクリックまでメニューが開いたままで、アプリはアクティブ化しなかった
  （3 回中 3 回）。
- net-meter 自身の項目の画像は、色付き・テンプレートとも、`MenuBarExtra` のラベルとしてそのまま表示され、
  毎秒更新される（両方の描き方を撮影）。

## Decision

1. パネルは `.menuBarExtraStyle(.window)` の `MenuBarExtra` にし、中身は `PanelView` とする。アプリは
   SwiftUI の `App` になる。項目のラベルは `StatusRenderer.image(...)` を `Image(nsImage:)` で出す —
   描画の関数は引き続き 1 つ（ADR-0002）。
2. 窓を自前で持つために要っていたもの — ~~`PanelWindow`~~、位置の計算、クリック監視と ~~`PanelToggle`~~、
   Space・他アプリの監視 — は取り除く。ただし下の検証で SwiftUI が各場面を扱うと確かめられた場合に
   限る。扱わない場面があれば、作り直さずに残す。（すべての場面を扱ったので、すべて取り除いた。）
3. そのまま残すもの: 計測、`MeterController`、`StatusRenderer`、パネルのモデルとビュー、
   `PanelUpdateGate`（パネル内のメニューが開いている間は、今も更新を差し込んではならない）、単一
   インスタンスのガード、ログイン項目、そして「権限を求めず、接続を開かない」という規則。

## リリース前の検証

リリース版で、Context と同じ合成クリックと撮影を用いる:

- 開いている間はハイライトが保たれ、閉じれば消える（5 回）;
- LaunchServices 起動直後に開いたポップアップメニューが開いたままでいる（3 回の起動）;
- 閉じ方ごと: 外側のクリック、項目のクリック、Esc、別のアプリが前面に来る、Space の切り替え;
- 閉じている間にパネルが SwiftUI の仕事をしないこと（ADR-0003 の決定 7）— 仮定せず測る;
- ラベルの 2 つの描き方、単位と表示の切り替え、パネルを開いたままの項目の幅の変化;
- リリース前のメンテナによる手での確認。

## 検証の結果（2026-09-21、macOS 27.0）

記録機能を組み込み、別のバンドル識別子にしたリリース相当のビルドを、インストール済みの v0.1.1 の横で
動かして測った。手での確認は、同じソースを記録機能なしでビルドしたもので行った。

| 確認項目 | 結果 |
|---|---|
| 開いている間のハイライト（5 回の開閉、撮影） | 毎回保たれ、消えたコマは無い。閉じるたびに消える |
| LaunchServices 起動直後のポップアップメニュー | 次のクリックまで開いたまま（3 回の起動で 3 回）。アプリは前面に来なかった |
| メニューバーの空き領域のクリック | パネルが閉じた |
| 別のアプリの窓のクリック | パネルが閉じた |
| 項目のクリック | パネルが閉じた（5 回中 5 回） |
| Esc、Space の切り替え | パネルが閉じた（手での確認） |
| パネルを開いたままの表示モードの変更 | 項目の幅が変わり、窓が追従した（手での確認） |
| ラベル（テンプレート・色付き） | どちらも描かれ、毎秒更新された（撮影） |
| ラベルに渡る明暗 | システムは `Aqua`、メニューバーは `VibrantDark` で、`colorScheme` は `dark` — メニューバーに従う |
| 閉じている間の仕事 | 中身は最初に開いたときに一度だけ作られ、保持される。30 秒の CPU 時間は v0.1.1 と同じ: 開く前 0.43 秒 対 0.42 秒、使った後 0.48 秒 対 0.49 秒 |
| アドレスのコンテキストメニューからのコピー、全体の見た目 | 問題なし（手での確認） |

未実測: 最低対応の macOS 26。パネルを開いたままの単位の切り替え。

## Consequences

- パネルを開いている間、項目が他のメニューバー項目と同じ見え方になる。
- 位置・素材・閉じ方は SwiftUI の持ち物になる。net-meter が自分で直すことはできなくなり、SwiftUI の
  扱いがまずい場面が見つかれば、パッチではなく新しい決定が要る。
- `MenuBarExtra` の窓をコードから閉じる公開の手段は無い。終了は引き続き効き、パネルの中でほかに窓を
  閉じる必要があるものは無い。
- 既知の制限は残る: 画面の表示領域より背の高い内容は切れる。

## Alternatives considered

- **パネルのまま、ハイライトが無いことを既知の制限として記録する。** 検証が通らなかった場合の戻り先。
- **popover の非公開の表示メソッドをパネルに対して呼ぶ。** 効く（3 回中 3 回、明滅なし）が不採用 —
  非公開 API は使わない。
- **`NSPopover` に戻す。** ハイライトは得られるが ADR-0003 の不具合が戻る（2 回中 2 回再現）。

# RFP: net-meter

> Generated: 2026-09-20
> Status: Draft

## 1. Problem Statement

macOS のメニューバーで、いま使っているネットワークインターフェース（以下 IF）の
上り/下り通信量をリアルタイムに把握したい。これができる既存アプリは、CPU・メモリ・
センサー等をまとめた統合モニタの一機能として提供されており、不要な機能・常駐コスト・
設定の複雑さが付いてくる。net-meter は「1 つの IF の現在の通信量を、数値とグラフで
メニューバーに出す」ことだけに特化する。

対象ユーザーは、通信状況を常時視界に置きたい macOS 利用者（第一に作者自身）。

## 2. Functional Specification

### Commands / API Surface

メニューバー常駐の GUI アプリ（Dock アイコンなし）。CLI は持たない。

**IF の選択**

| モード | 挙動 |
|--------|------|
| 自動（既定） | OS の優先順で先頭にある物理 IF（Wi-Fi または有線 Ethernet）を表示する。VPN のトンネル IF（`utun` 等）は選ばず、その下で実際に通信を運んでいる物理 IF を表示する。IF の切替（Wi-Fi ⇔ 有線など）には自動で追従する |
| 手動 | 一覧（表示名 + BSD 名、例:「Ethernet (en0)」）から 1 つ選ぶ |

- 手動で選んだ IF が消えたとき（USB アダプタを抜く等）は「不在」を表示して待ち、
  IF が戻れば自動で再開する。別の IF へ黙って切り替えない。
  「不在」は 0 KB/s（通信なし）と見分けがつく表示にする。
- 自動選択で該当する物理 IF が 1 つも無いときも、同じ「不在」表示にする。

**メニューバー表示**

| 表示モード | 内容 |
|------------|------|
| 数値 + グラフ（既定） | 2 行の数値と、その右のグラフ |
| 数値のみ | 2 行の数値 |
| グラフのみ | グラフ |

- 数値は上段が上り（↑）、下段が下り（↓）。幅は固定し、等幅数字を右寄せにする
  （桁が変わるたびに隣のアイコンが動くのを防ぐ）。
- グラフは中央を原点とし、上りを上方向、下りを下方向に描く。窓は約 60 秒。
- 縦軸は線形の自動スケール（窓内の最大値に追従）。フルスケールに下限を設け、
  アイドル時の微小な通信がグラフ一杯に見えるのを防ぐ。上りと下りは同じスケールを使う。
- 色はモノクロが既定（メニューバーの明暗に追従）。設定で上り/下りの色分けに切り替えられる。
- 更新間隔は 1 秒固定。
- グラフの幅・線の太さ・下限値などの見た目の細部は、実機のメニューバーで調整して決める。

**単位**

- 既定はバイト/秒（KB/s・MB/s・GB/s）。設定でビット/秒（kbps・Mbps・Gbps）に切り替えられる。
- 接頭辞は SI（1 MB = 1000 KB）。Finder やアクティビティモニタに合わせる。

**パネル（メニューバー項目をクリック）**

- 履歴グラフ（固定 3 分窓、最新が右端）
- 現在値（上り/下り）
- IF 名（表示名・BSD 名・自動/手動の別）
- IF の素性（IP アドレス、リンク速度）
- 履歴窓内のピーク値（上り/下り）
- 起動後の累積転送量（上り/下り）。IF ごとに保持し、メモリ上だけに持つ
- 設定: IF 選択、表示モード、単位、色、ログイン時に起動
- 終了

### Input / Output

- 入力: OS が公開している IF 別の累積バイトカウンタ、IF の優先順と種別、IF の表示名。
- 出力: メニューバー項目とパネルの描画のみ。ファイル出力・標準出力・ネットワーク送信は無い。
- 履歴はメモリ上のリングバッファだけに持ち、永続化しない。

### Configuration

- `UserDefaults` に保存する。設定ファイルは持たない。
- ログイン時の起動は `SMAppService` のトグル（既定 OFF）。

### External Dependencies

なし。OS 標準フレームワークのみを使う。アプリ自身はネットワーク通信を一切しない。

## 3. Design Decisions

**言語・フレームワーク**

- Swift 6（strict concurrency）/ Swift Package Manager。
- メニューバーの描画は AppKit の `NSStatusItem` に自前描画する。SwiftUI の
  `MenuBarExtra` は、2 行のカスタムレイアウトと毎秒の更新に向かないため使わない。
- パネルは SwiftUI を `NSPopover` に載せ、履歴グラフは Swift Charts で描く。
  パネルの内容は開いたときに生成し、閉じたら解放する。
- 対応環境は macOS 26 以降・Apple Silicon 専用。

**データの読み方**

- カウンタは `sysctl`（`NET_RT_IFLIST2`）で、1 秒に 1 回、全 IF 分をまとめて読む。
  IF ごとのリングバッファに積むので、表示する IF を切り替えた直後でも実際の履歴が出せ、
  累積転送量も IF ごとに持てる。
- 差分は常に 2^32 を法として取る。カウンタが 32bit に切り詰められていても、
  真の 64bit であっても、1 サンプルあたりの増分が 4 GiB 未満なら正しい値になる
  （§7 参照）。1 秒間隔なら約 34 Gbps まで一意に決まる。
- カウンタの巻き戻りと、リセット（トンネル IF の再生成、スリープ復帰など）は区別する。
  リセットと判定したサンプルは捨てて再基準化する。判定規則（パケット数カウンタの後退、
  リンク速度 × 経過時間の上限など）は Phase 1 で実測して決め、ADR に残す。
- 速度は単調時計で測った実経過時間で割る。タイマーは間引かれるため、1 秒と仮定しない。
- 自動選択は `NWPathMonitor` が返す優先順から、種別が Wi-Fi または有線 Ethernet の
  最初の IF を取る。同じ IF が重複して返るため重複を除く。

**テスト容易性**

- 差分とリセット判定、IF の解決、数値の整形（固定幅・単位切替）、スケール計算は純関数にまとめる。
- カウンタの読取層と IF の情報源はプロトコルで注入し、テストでは差し替える。

**既存ツールとの関係**

- load-spinner（CPU/GPU 負荷のメニューバー表示）と対になる。構成・署名・配布の型も踏襲する。

**スコープ外**

- プロセス別の通信量（必要な API が非公開）
- メニューバーでの複数 IF 同時表示
- 履歴の永続化・エクスポート、月次の使用量管理
- 通知・しきい値アラート
- 速度テスト、パケットキャプチャ
- CLI
- Intel Mac、macOS 25 以前

## 4. Development Plan

### Phase 1: Core

- 読取層、差分・巻き戻り・リセット判定、自動選択の解決、数値の整形、スケール計算を実装し、
  単体テストを付ける。
- 実機確認（計測スクリプトは `spikes/` に置き、出荷物に含めない）:
  - macOS 27 実機と macOS 26 の検証用 VM でのカウンタ挙動。
    macOS 26 で 32bit 切り詰めが起きるかは、4 GiB を超える通信を流して確かめる
  - split tunnel 構成の VPN 接続中に、自動選択が物理 IF を返すこと
  - スリープ復帰、IF の抜き差し、Wi-Fi ⇔ 有線の切替
  - リンク速度として読める値が Wi-Fi で妥当か
- リセット判定の規則を確定し、ADR に記録する。

### Phase 2: Features

- `NSStatusItem` の描画（3 表示モード、固定幅、モノクロ/色付き、「不在」表示）。
- パネル（履歴グラフ、現在値、IF 情報、ピーク値、累積転送量、設定）。
- 設定の永続化、ログイン時起動、シングルインスタンスガード。
- 実機のメニューバーで見た目を調整する（明暗両方、ノッチのある機種を含む）。
- 常駐時の CPU 負荷を実測する。

### Phase 3: Release

- README（英語・日本語）、AGENTS.md、CHANGELOG、ADR。
- アプリアイコン。
- 署名、notarize、Homebrew cask、GitHub Release。
- util-series への submodule 追加、org プロフィールと Web カタログの更新。
- 再利用できる知見を knowledge リポジトリに還元する
  （非特権プロセスから見えるカウンタの挙動など）。

各 Phase は独立にレビューできる。設計確定時とリリース前に、独立した検証パスを入れる。

## 5. Required API Scopes / Permissions

None.

TCC の許可、entitlement、管理者権限はいずれも不要。アプリ自身はネットワーク通信をしない。
この性質は維持要件とする。

## 6. Series Placement

Series: util-series
Reason: メニューバー常駐の単機能 GUI ユーティリティで、同シリーズの load-spinner と
同じ型（構成・署名・配布）を取る。外部サービスにも LLM にも依存しない。

## 7. External Platform Constraints

**カウンタの精度（実測）**

非特権のサードパーティプロセスが `sysctl`（`NET_RT_IFLIST2`）で読める IF 別のバイトカウンタは、
構造体のフィールド幅こそ 64bit だが、OS が値を加工して返す。同時刻の OS 付属 `netstat -ib` は
加工されていない値を返すため、突き合わせて確認した。差の理由は未確認。

| 環境 | 1 KiB 単位への切り捨て | 32bit への切り詰め |
|------|------------------------|--------------------|
| macOS 27.0（実機） | あり | あり（真値を 2^32 で割った余りになる） |
| macOS 26.6.2（VM） | あり | 未確認（カウンタが 4 GiB 未満だったため。Phase 1 で確認） |

設計への帰結:

- カウンタは 4 GiB ごとに巻き戻る（9 MB/s なら約 8 分ごと）。「フィールドが 64bit だから
  巻き戻りの処理は不要」とは言えない。
- 分解能は 1 サンプルあたり 1 KiB。KB/s〜MB/s の表示には十分だが、1 KB/s 未満では
  0 と 1.0 KB/s を行き来する。
- 値は IF 全体の L2 トラフィックで、LAN 内の通信（NAS 宛など）も含む。
  VPN 接続中に物理 IF を表示する場合は、カプセル化のオーバーヘッド分も含む。

**メニューバー**

- 高さは約 22pt。2 行の数値は 9pt 前後の文字になる。
- ノッチのある機種では、項目の合計幅が広いと OS が項目を隠す。3 つの表示モードで
  幅を選べることに、実用上の意味がある。
- メニューバーは壁紙で着色され、明暗も切り替わる。色付き表示は両方で読める配色を実機で詰める。

**パネル**

- Dock アイコンを持たないアプリの popover には、フォーカス、自動クローズ、
  非表示中のレイアウトコストに関する既知の注意点がある。実装前に既存ツールの知見を確認する。

**検証環境の限界**

- macOS 26 の検証環境は VM で、仮想 NIC だけを持つ。Wi-Fi と VPN は無い。
  macOS 26 で確かめられるのはカウンタの挙動と外観までで、IF の自動選択と VPN 下の挙動は
  macOS 27 の実機でのみ確認する。

## Discussion Log

1. **実現可能性の確認（2026-09-20）** — 約 60 行の Swift スパイクで、プライマリ IF の取得、
   IF の表示名の取得、バイトカウンタの読取が権限なしでできることを macOS 27 実機で確認した。
   このとき、非特権プロセスから見えるカウンタが 32bit 切り詰め + 1 KiB 切り捨てになっていることが
   判明した（`netstat` の値を前後に挟んで突き合わせた）。
2. **ツール名** — `net-meter` に決定。`-lens` 系は履歴を蓄積・分析するツール群であり、
   蓄積を持たない瞬時表示の本ツールとは性格が違うため採らなかった。
   他の候補は `netif-meter`、`net-pulse`、`net-lens`。
3. **VPN 接続中の自動選択** — 物理 IF を優先すると決定。OS のプライマリ（`utun`）に従う案は、
   split tunnel 構成でトンネル外の通信が見えなくなるため採らなかった。設定で切り替える案は、
   設定項目と検証対象が増えるため採らなかった。`utun` を手動で固定する使い方は、
   番号が接続のたびに変わりうるため壊れやすい。追加のスパイクで、`NWPathMonitor` が
   優先順と種別つきで IF を返すことを確認した（同じ IF が重複して返る）。
   VPN 接続中の挙動は未確認で、Phase 1 の検証項目とした（split tunnel の VPN 環境あり）。
4. **単位** — バイト/秒を既定とし、ビット/秒へ切り替えられるようにする。
5. **手動選択した IF の消失** — 「不在」を表示して待つ。消えている間だけ自動選択へ切り替える案は、
   手動で選んだつもりの IF と別の数値が出て誤読の余地があるため採らなかった。
6. **CLI** — 付けない。診断用の `doctor` サブコマンドを同梱する案は採らなかった。
   実機確認には `spikes/` の計測スクリプトを使う。
7. **グラフ** — 中央を原点に、上りを上方向、下りを下方向に描く（利用者の指定）。
   同じ枠に重ねて描く案は、区別を色だけに頼ることになるため採らなかった。
   縦軸は線形の自動スケール + 下限。対数の固定レンジ、リンク速度での固定は採らなかった。
8. **色** — モノクロを既定とし、色付きへ切り替えられるようにする。
9. **クリック時の UI** — パネル（popover）に決定。メニューのみの案も検討したが、
   履歴グラフと IF 情報を見られることを優先した。パネルには基本構成に加えて、
   IF の素性（IP アドレス・リンク速度）、ピーク値、起動後の累積転送量を載せる。
10. **最小 OS** — macOS 26 以降。当初は検証用の実機で macOS 26 を確かめる想定だったが、
    その実機が macOS 27 へ更新済みと判明したため、macOS 26.6.2 の VM を用意して検証環境とした。
    この VM で 1 KiB 切り捨てを確認した。32bit 切り詰めの確認は Phase 1 に回した。
11. **仮決め（慣例に従い、異論なし）** — 更新間隔 1 秒固定、SI 接頭辞、設定は `UserDefaults`、
    ログイン時起動は既定 OFF、上りと下りは共通スケール、メニューバーのグラフ窓は約 60 秒、
    パネルの履歴窓は固定 3 分、Apple Silicon 専用。
